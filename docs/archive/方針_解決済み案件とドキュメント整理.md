# 解決済み案件の扱いとドキュメント整理 — Cursor の提案まとめ

## 結論

- **Cursor のチャット・Todo** → 自動削除は Cursor 製品側の機能。このリポジトリでは制御できない。
- **このプロジェクトのドキュメント** → ルールを決めれば「自動で archive に移す」スクリプトを追加できる。削除は手動推奨。
- **チャットサポートの「案件」データ** → 案件テーブルを用意すれば「解決済み＋○日経過でアーカイブ／削除」は実装可能。

---

## 1. Cursor のチャット・タスクについて

- チャット履歴やチャット内の Todo（タスク）を「解決済みなら自動で消す」のは **Cursor の製品機能**。
- このリポジトリにコードを足して実現することはできない。
- 必要なら Cursor の設定やサポートで、履歴・タスクの扱いを確認する。

---

## 2. プロジェクト内ドキュメント（docs）の整理

### いまやっていること

- **docs/README.md** … ドキュメント一覧（索引）。増えても「まず README」でたどれる。
- **docs/archive/** … 過去の検討・メモを移す場所。直下が増えすぎないようにする。

### 今後つけられる「自動で片付ける」機能

- **自動削除** … 可能だが、誤削除のリスクがあるため **非推奨**。
- **自動で archive に移す** … **推奨**。
  - 例: ファイル名が `diagnosis-*.md` のもの、または「○日更新されていないメモ」を `docs/archive/` に移すスクリプト。
  - 削除はせず、archive に移したあと、必要なら手動で削除する。

### ルール（docs/README.md に記載済み）

- 新規ドキュメントを増やしたら、**docs/README.md の該当カテゴリに1行追加**する。
- 一時メモや完了した検討は、必要なら **docs/archive/** に移動する。
- 日付付きの診断メモ（`diagnosis-*.md` など）は、古くなったら **archive に移す**。

---

## 3. チャットサポートの「案件」データ（将来）

- 「案件」を D1 などで管理するテーブルを用意する場合:
  - 案件に「状態」（未対応・対応中・解決済み）を持たせる。
  - バッチや Cron で「解決済みかつ○日経過」のものを **削除 or 別テーブルにアーカイブ** する処理は **実装可能**。
- 現状のリポジトリには「案件」用テーブルはないため、必要になったら設計から対応する。

---

## まとめ

| 対象 | 自動削除 | 自動で archive に移す | 備考 |
|------|----------|------------------------|------|
| Cursor のチャット・Todo | 製品側の機能（要確認） | — | リポジトリでは制御不可 |
| docs 内のファイル | 非推奨（誤削除リスク） | スクリプトで可能 | ルールは README に記載 |
| 案件データ（将来） | 実装可能 | 実装可能 | テーブル設計から必要 |

この方針で整理を進めると、解決済みの扱いとドキュメントの肥大化を抑えられます。
